## Uruchamianie

Otwórz folder wybranej lekcji w edytorze. Kod z `startery/` kopiuj do własnego folderu `praca/`. Każde zadanie wykonuj w osobnej kopii, zgodnie z jego poleceniem. Folder `rozwiazania/` służy do porównania po własnej próbie. W lekcjach ocenianych właściwe polecenie przekazuje nauczyciel.

Na Windows poniższe polecenia wykonuj w terminalu. Jeśli na Twoim stanowisku działa `python` zamiast `py`, użyj go w pierwszym poleceniu:

```text
py -m venv .venv
.venv\Scripts\python.exe --version
```

Gdy zadanie korzysta z zewnętrznych pakietów, skopiuj też do pracy jego `requirements.txt` i zainstaluj zależności w utworzonym środowisku:

```text
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

W VS Code wybierz interpreter z `.venv` poleceniem **Python: Select Interpreter**. Samo wybranie interpretera w edytorze nie zmienia każdego otwartego terminala. Pełna ścieżka poniżej jednoznacznie wskazuje używane środowisko:

```text
.venv\Scripts\python.exe main.py
.venv\Scripts\python.exe -m unittest discover -v
```

`main.py` zastąp nazwą pliku z zadania. Testy uruchamiaj z folderu wskazanego w poleceniu, zawierającego odpowiednie pliki `test_*.py`. Oprócz `OK` sprawdź liczbę wykonanych testów. `Ran 0 tests` oznacza, że niczego nie sprawdzono.

Na Linux/macOS odpowiednikami są `python3 -m venv .venv` oraz `.venv/bin/python`. W lekcjach Django, FastAPI, PyQt i Docker obowiązują dodatkowo instrukcje z README danej lekcji. Nie instaluj wszystkich pakietów całego kursu przed pierwszym ćwiczeniem.

Materiały korzystają z różnych zapisów `py`, `python` i `python3`, zależnie od przykładu. Zawsze uruchamiaj kod interpreterem wybranym dla danego zadania. Numer tematu różni się od numeru godziny: **temat 37 to lekcje 73–74**.
